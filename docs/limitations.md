# Limitations and validity boundaries

## Simulator and measured quantities

All retained experiment results were generated by **Simplified Python FANET Model — NOT NS-3** on Windows/Python 3.13.2. It is a deterministic, time-stepped abstraction with waypoint mobility, distance-based neighbor connectivity, graph routes, and per-packet event outcomes. It does not implement propagation, PHY/MAC, interference, contention, retransmission, protocol stacks, energy, or per-hop/queueing delay. Delivered application-byte throughput is derived from packets delivered and configured duration; it is not PHY throughput. Delay and control/signaling overhead are **not modeled/measured**, never zero-valued substitutes.

The simulator's topology, traffic, queue-free packet progression, and drop outcomes are simplified. No claim transfers to radio-realistic deployments without a validated NS-3 or field evaluation. The `simulation/ns3/fanet_simulation.cc` starter is prepared/unvalidated and has not been compiled or executed; the Python backend is never a silent NS-3 fallback.

## Trust and detection

Trust equations, component weights, priors, temporal rates, and cutoffs are implementation choices because the project source PDFs do not prescribe them or validate their calibration. Trust is available only for an observed next-hop outcome and is relational. Indirect trust depends on observed peer opinions; absent information is left unavailable.

Detection is a deterministic weighted rule, not a calibrated probability. Evaluation reports node-level alerts (a node is positive if any scored window becomes suspicious/malicious); window-level counts are descriptive and not the reported node-level confusion matrix. The 200 m p=.25 matrix still misses 9 of 20 attacked-node cases. The seed-42 demonstration's perfect node score is not a generalization estimate.

## Routing

The trust-aware route score combines configured hop, forwarding reliability, and link stability preferences. It has no learned physical delay or signaling cost. A single attacker placement (UAV 7), one traffic model, and 20 paired seeds at p=.8 are not enough to establish universal benefit. The comparison is descriptive; no formal significance test was specified or performed. Exposure is evaluated after route selection using the known attacker ID; the route policy does not consume it.

## Machine learning and explainability

The Random Forest uses 16,000 held-out temporal rows from four seeds, grouped away from training seeds. Rows within a run are correlated; the effective independent holdout groups are four seeds, not 16,000 independent simulations. The held-out malicious F1 is 0.679, with recall 0.610. ROC-AUC and average precision are ranking summaries on this same grouped test set and do not remove seed/generalization limitations. ML is a separate retrospective baseline, not asserted to beat the deterministic detector.

SHAP TreeExplainer values are calculated for the saved Random Forest, with feature order checked against the saved schema. Global values use a deterministic sample of 512 held-out rows; local values explain one prediction. SHAP describes model attribution, not causal effects. LIME was not implemented; SHAP was selected as the primary explainability method.

## Scope of attacks and environment

Only probabilistic packet-drop and deterministic transit blackhole behaviors are implemented and tested. Other scenario YAML files are placeholders, not executed attack evidence. Python 3.13.2, NumPy 2.1.3, pandas 2.3.0, scikit-learn 1.5.2, SHAP 0.54.1, and Streamlit 1.66.0 were observed in the validated environment. Requirements use lower bounds rather than a complete cross-platform lockfile. The shared environment's `pip check` reports FastAPI 0.115.5 conflicts with Starlette 1.9.0 (introduced with Streamlit); use an isolated environment. LIME is neither implemented nor required.
